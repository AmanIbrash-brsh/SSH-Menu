# SSH Menu

Быстрое меню SSH для администраторов: по горячей клавише открывается список серверов из `~/.ssh/config`, ищешь по паре букв и подключаешься. Всё управляется с клавиатуры. В меню видно, жив ли сервер и пускает ли он по ключу, а в боковой панели показано его состояние: нагрузка, диски, обновления, упавшие сервисы.

Одна программа без зависимостей: один файл `ssh-menu` на Go со встроенным [fzf](https://github.com/junegunn/fzf). Нужен только системный `ssh`. Работает на любом Linux, в любом терминале и окружении (GNOME, KDE, Hyprland, Sway и другие). Отдельной базы нет: источник данных — ваш `~/.ssh/config`.

## Возможности

- **Подключение**: `Enter` — ssh, `Alt+T` — ssh сразу в tmux-сессию `main` (переживает обрыв связи). Можно ввести `user@host`, которого нет в списке.
- **Статус в списке**: ● зелёный — порт отвечает, красный — нет, жёлтый — хост за ProxyJump. Рядом пометка, если вход по ключу не работает: `password`, `no access`, `host key changed`.
- **Панель сведений**: адрес, ключ, ping, ОС, uptime, load, память, диски (заполненные подсвечиваются), число обновлений (отдельно security), «нужна перезагрузка», упавшие systemd-юниты, docker. Данные из кэша показываются мгновенно и обновляются в фоне. На сетевых устройствах и git-серверах без shell команды не выполняются.
- **Файлы с прогресс-баром**: `Alt+U` — загрузить файлы и папки на хост или сразу на несколько (параллельно, полоса и скорость по каждому хосту), `Alt+D` — скачать (обзор папок прямо в меню) в `~/Загрузки/<хост>/`, `Alt+F` — открыть хост в файловом менеджере (sftp).
- **Несколько хостов**: `Tab` — отметить, `Alt+X` — выполнить команду на всех (одинаковые ответы склеиваются), `Alt+B` — broadcast (tmux-панели, ввод идёт во все), `Alt+K` — разослать SSH-ключ.
- **Сохранённые команды**: в `Alt+X` можно выбрать команду из своих заготовок (★) или из недавних; `Alt+S` сохраняет набранную.
- **Группы и PROD**: группы и пометка PROD хранятся комментариями в `~/.ssh/config`. `Alt+←/→` показывает одну группу, `Alt+P` переключает «все / без PROD / только PROD». Окно PROD-сессии подкрашивается красным, а массовые действия на PROD-хостах требуют подтверждения.
- **Сменился ключ хоста** (после переустановки сервера): меню показывает старый и новый отпечатки и предлагает забыть старый ключ.
- **Правка**: `Alt+N` — мастер нового хоста, `Alt+E` — открыть хост в редакторе, `Alt+G` — группа, `Alt+R` — PROD. Перед каждым изменением `~/.ssh/config` делается бэкап. Хосты из файлов, подключённых через `Include`, тоже видны.
- `Alt+W` — веб-интерфейс хоста, `Alt+Y` — скопировать `user@host:port`, `Ctrl+R` — перепроверить всё, **`Alt+H` — все клавиши**.

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/AmanIbrash-brsh/SSH-Menu/main/install.sh | sh
```

Права root не нужны: программа ставится в `~/.local/bin`. Установщик скачивает готовый бинарник последнего релиза (x86_64 или arm64) и проверяет его sha256. Обновление — та же команда. Удаление — `uninstall.sh` (настройки и история остаются).

Другие способы:

```bash
go install github.com/AmanIbrash-brsh/SSH-Menu/cmd/ssh-menu@latest   # если есть Go

git clone https://github.com/AmanIbrash-brsh/SSH-Menu.git            # сборка из исходников
cd SSH-Menu && ./install.sh --source
```

### Вручную из архива

Если архив скачан со [страницы релизов](https://github.com/AmanIbrash-brsh/SSH-Menu/releases/latest) (`ssh-menu_linux_amd64.tar.gz` для обычных ПК, `arm64` для ARM), внутри один исполняемый файл `ssh-menu`:

```bash
tar -xzf ssh-menu_linux_amd64.tar.gz      # распаковать
mkdir -p ~/.local/bin
mv ssh-menu ~/.local/bin/                 # положить туда, где система ищет программы
ssh-menu doctor                           # проверить, что всё на месте
```

Если команда `ssh-menu` не находится, значит `~/.local/bin` нет в `PATH`: запускайте по полному пути `~/.local/bin/ssh-menu`. Программу можно запускать и прямо из папки, куда она распакована (`./ssh-menu`). При ручной установке ярлык в меню приложений не создаётся; его добавляет `install.sh`.

## Первые шаги

1. **Серверы берутся из `~/.ssh/config`.** Если файл пустой, запустите `ssh-menu` и нажмите `Alt+N`: мастер спросит имя, адрес и пользователя и сам запишет хост.
2. **Запуск**: `ssh-menu` в терминале, либо `ssh-menu popup` — отдельным окном (эту команду удобно повесить на горячую клавишу, см. ниже).
3. **Подключение**: начните печатать имя сервера, список сузится; `Enter` подключает, `Esc` закрывает меню.
4. **Все клавиши** показывает `Alt+H` прямо в меню.

`ssh-menu doctor` показывает, что найдено в системе и какую функцию отключает отсутствие каждой программы. Обязателен только `ssh`. Необязательные:

| Программа | Для чего |
|---|---|
| `tmux` | `Alt+B` broadcast |
| `wl-clipboard` / `xclip` / `xsel` | `Alt+Y` копирование |
| `zenity` / `kdialog` | окно выбора файлов для `Alt+U` (без него — встроенный обзор папок) |
| `libnotify` (`notify-send`) | уведомления |

На серверах для `Alt+U` / `Alt+D` нужен `tar` (есть практически везде).

## Горячая клавиша

Запускать стоит команду `ssh-menu popup`: она открывает меню в отдельном окне. В самом терминале можно просто набрать `ssh-menu`. Окно меню получает класс `ssh-menu`, по нему его удобно сделать плавающим.

**GNOME**: Настройки → Клавиатура → Комбинации клавиш → Дополнительные комбинации → `+`, команда `~/.local/bin/ssh-menu popup`. В GNOME `Super+S` по умолчанию открывает быстрые настройки, поэтому выберите другую клавишу или сначала освободите эту.

**KDE Plasma**: Параметры системы → Клавиатура → Комбинации клавиш → Добавить → Команда, `~/.local/bin/ssh-menu popup`.

**Hyprland** (`hyprland.conf`):
```
bind = SUPER, S, exec, ~/.local/bin/ssh-menu popup
windowrulev2 = float, class:^(ssh-menu)$
windowrulev2 = size 1400 780, class:^(ssh-menu)$
windowrulev2 = center, class:^(ssh-menu)$
```

**Sway**:
```
bindsym $mod+s exec ~/.local/bin/ssh-menu popup
for_window [app_id="ssh-menu"] floating enable, resize set 1400 780
```

Меню открывается плавающим окном, а после подключения на Hyprland и Sway окно становится обычным, как любой терминал.

## Как хранятся группы и пометки

Всё лежит в `~/.ssh/config` в виде комментариев прямо над строкой `Host`. ssh их игнорирует, так что конфиг остаётся обычным:

```
# group: Proxmox
# env: prod
# url: https://10.0.0.11:8006
Host pve1
    HostName 10.0.0.11
    User root
```

- `group` — группа (цветная колонка, фильтр `Alt+←/→`);
- `env: prod` — PROD: красная пометка, красное окно, подтверждение массовых действий;
- `url` — адрес для `Alt+W`; если его нет, меню спросит адрес при первом нажатии и сохранит.

Блок `Host *` с настройками по умолчанию держите **последним**: ssh берёт первое найденное значение. Новые хосты из `Alt+N` вставляются перед ним.

Совет: добавьте в `Host *` мультиплексирование. Тогда повторные подключения, панель сведений, `Alt+X` и файлы работают мгновенно:

```
Host *
    ControlMaster auto
    ControlPath ~/.ssh/sockets/%C
    ControlPersist 10m
```
(и один раз выполните `mkdir -p ~/.ssh/sockets && chmod 700 ~/.ssh/sockets`)

## Настройки

Файл `~/.config/ssh-menu/config` создаётся при первом запуске, все параметры в нём закомментированы:

| Параметр | Что задаёт | По умолчанию |
|---|---|---|
| `SSHM_TERMINAL` | терминал для окна меню и broadcast | первый найденный: kitty, foot, alacritty, wezterm, ghostty, konsole, ptyxis, gnome-terminal, xfce4-terminal, xterm |
| `SSHM_TERMINAL_ARGS` | доп. опции терминала, например `"-o font_size=12"` | — |
| `SSHM_BROWSER` | браузер для `Alt+W` | `xdg-open` |
| `SSHM_FILES` | файловый менеджер для `Alt+F` | nautilus, иначе `xdg-open` |
| `SSHM_EDITOR` | редактор для `Alt+E` | `$EDITOR`, micro, nano, vim |

Заготовки команд для `Alt+X` — в `~/.config/ssh-menu/snippets`, по одной на строку.

## Где лежат данные

`~/.local/state/ssh-menu/`:
- `history` — частота подключений (по ней сортируется список), `cmd_history` — команды из `Alt+X`;
- `status.tsv`, `auth.tsv`, `resolve.json`, `stats/` — кэш статусов, проверки ключей, параметров ssh и сведений о системе;
- `backups/` — 20 последних копий `~/.ssh/config`.

Проверка входа по ключу выполняется не чаще раза в 12 часов, а также по `Ctrl+R` и после `Alt+K`. Она открывает обычное ssh-соединение с `BatchMode` и командой `true`. Сведения о системе собираются только чтением: `/proc`, `df`, `systemctl --failed`, `apt-get -s` / `dnf -C check-update`, `docker ps`.

## Разработка

```bash
make build        # собрать ./ssh-menu
make test         # go vet + тесты
SSHM_TEST_HOST=<не-prod хост> go test -tags live -run Live ./internal/app -v   # живой тест передачи файлов
```

```
cmd/ssh-menu/        точка входа
internal/app/        меню и все действия (подключение, файлы, команды, ключи, правка)
internal/sshcfg/     разбор и правка ~/.ssh/config
internal/hosts/      параметры ssh, проверка доступности и ключей, фильтры
internal/stats/      сбор сведений о системе
internal/ui/         отрисовка списка, панели и справки
internal/desktop/    браузер, буфер обмена, окно терминала, уведомления
internal/fz/         встроенный fzf
```

Прежняя версия на bash и Python сохранена под тегом `v0.1.0-bash`.
